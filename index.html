ManyBalloons

Cosmetic balloons that float at your side — with real ropes, living motion and custom models. For Paper 1.21+.

Paper 1.21+ Java 21 17 balloons No resource pack

ManyBalloons gives your players something to wear that actually moves. Each balloon is a small flying model tethered to the player with a real rope: it swings when you run, drifts in the wind, lifts when you swim and shudders when a mob gets close. The models are built from textured heads and item displays, so everything ships with the plugin — no resource pack to ask players to install.

Every balloon is defined in a single YAML file and every motion is a YAML animation, so adding your own is editing a text file, not writing code.

What you get

  • Custom models — textured heads, item displays, or a composite model assembled from up to dozens of parts.
  • Items from your item plugin — render an ItemsAdder, Oraxen or Nexo item as a balloon, a part, a flipbook frame or a category icon.
  • A real rope — an invisible leashed entity the client draws as a string, so it looks right from every angle.
  • 17 balloons in 3 categories — Classic, Cute and Space ship by default.
  • Living physics — swinging, trailing and buoyancy, plus ambient wind and reactions to damage, water and nearby mobs.
  • A YAML animation engine — 7 channels and 6 wave shapes. The bundled Solar System is a working orrery, not a decoration.
  • Flipbooks — cycle a list of frames to animate a static model.
  • Wear several at once — max_balloons in config, raised per player with manyballoons.slots.<n>.
  • Menus out of the box — a category menu, a filtered balloon list and an admin player list.
  • Multilingual — English, Spanish, German, French, Italian, Dutch, Polish, Brazilian Portuguese and Russian.
  • Optional crafting — give any balloon a shaped or shapeless recipe.
  • Integrations — a free Java API with cancelable events, and PlaceholderAPI placeholders.

Installation

What you need

ServerPaper 1.21 or newer (Folia is not supported)
Java21+
PlaceholderAPIOptional — only for the placeholders
ItemsAdder / Oraxen / NexoOptional — only to render their items as balloons
Resource packNot required — every texture is embedded

Setup

  1. Drop ManyBalloons.jar into your plugins/ folder.
  2. Start the server. It creates plugins/ManyBalloons/ with the config, the animation file, the language files and the balloons/ folder.
  3. Grant permissions — see Permissions. Regular players can open the menu at once; the balloons themselves are gated per node so you can sell them.
Where things go. The plugin JAR sits in plugins/. Everything you edit lives in plugins/ManyBalloons/: config.yml, animations.yml, lang/ and one file per balloon under balloons/<category>/.
Reloading. After editing any YAML, run /balloons reload — it re-reads the config, the messages, the animations, the balloons and the recipes in place. No restart needed.

Commands

Everything runs under /balloons (aliases /balloon and /mb).

CommandWhat it does
/balloonsOpen the category menu and pick a balloon. Needs manyballoons.use.
/balloons set <id>Equip a balloon by id. A bare /balloons set opens the menu instead.
/balloons set <id> <player>Give a balloon to another player. Needs manyballoons.admin.
/balloons clearRemove your balloons and forget your saved choice.
/balloons clear <player>Remove another player's balloons. Needs manyballoons.admin.
/balloons manageOpen the admin list of online players to inspect or clear their balloons. Needs manyballoons.admin.
/balloons reloadReload the config, messages, animations, balloons and recipes. Needs manyballoons.admin.
In the menu. Left-click a balloon to wear it, right-click one you're wearing to remove it and free the slot. The catalogue book in the menu opens a searchable list across every category.

Permissions

Anyone can open the menu, but a balloon is only equippable when its own node is held — which is what lets you sell them through a rank, crate or shop plugin.

NodeDefaultWhat it allows
manyballoons.usetrueOpen the menu and manage your own balloons.
manyballoons.adminopEverything: manage, giving or clearing other players' balloons, reload, every balloon and unlimited slots.
manyballoons.balloon.<id>opPermission to wear one specific balloon. The node is the permission field in the balloon's file.
manyballoons.slots.<n>falseLet the player wear up to n balloons at once. The highest matching n wins and overrides max_balloons.
Free for everyone? Set permission: "public" in a balloon's file (also accepts none or -). That balloon needs no node at all, so anyone with manyballoons.use can wear it.

general.protect_balloon_entitiesBlocks damage, interaction, targeting and leashing of the balloon's entities.

physics.inertiaHow much your movement drags the balloon.

Creating balloons

One file per balloon under plugins/ManyBalloons/balloons/<category>/<id>.yml. The file name is the id and the sub-folder is the category, so balloons/cute/heart.yml is the balloon heart in the category cute. A new sub-folder becomes a new category automatically. Rename a file to start with _, or set disabled: true, to park it.

The category menu is styled in config.yml under categories, so a category added here is styled by adding a matching key there.

A minimal balloon

display_name: "&cClassic Red"
material: PLAYER_HEAD
skull_texture: "<base64 profile texture>"
lore:
  - "&7A classic red balloon"
  - "&8Left-click to equip, right-click to remove"
animation: "float"
permission: "manyballoons.balloon.classic_red"
size: 1.0
offset:
  x: 0.7
  y: 1.8
  z: -0.4

Top-level keys

KeyWhat it does
display_nameName shown on the item, in the menus and in messages. Colour codes with &.
materialThe item whose model is rendered.
skull_textureBase64 profile texture, for PLAYER_HEAD models. Omit for a plain item.
custom_model_dataItem model id, when a resource pack adds one.
custom_itemRender an ItemsAdder, Oraxen or Nexo item instead of a material (see below).
loreTooltip lines shown with the menu item.
animationMotion name. A built-in like float, or any name defined in animations.yml.
permissionNode required to equip it. public, none or - mean everyone.
sizeScale of the main model. 1.0 is its natural size; parts keep their own scale.
offsetRest position of the balloon relative to the player: x (side), y (above the eyes, defaults to 1.6) and z (forward/back). Also accepted flat as offset_x/y/z.
trailParticle trail behind the main model: enabled, type, color, amount, scale, interval.
auraParticles hugging the balloon: enabled, type, amount.
partsExtra displays of a composite model (see below).
framesFlipbook frames cycled on the main model (see below).
recipeOptional crafting recipe (see below).
disabledtrue unloads the balloon without deleting the file.

Composite models

A balloon can be several displays at once. Each entry in parts is its own model with its own offset, scale, animation, trail and aura, which is what the Solar System and the UP! house are built from.

Part keyWhat it does
material, skull_texture, custom_model_data, custom_itemThe part's model, exactly like the top level.
offset_x, offset_y, offset_zPosition of the part relative to the balloon's rest spot, in blocks.
scaleAbsolute scale of this part.
ropetrue hangs the part from the main rope anchor on its own string — used by the UP! house balloons.
animationMotion for this part. NONE keeps it still. The reserved name orbit circles it around the balloon centre from its own offset.
trail, auraPer-part particles, with the same fields as the top level.

Flipbook frames

To animate a static model, list frames and the interval between them. Each frame is a model swap on the main display.

frames:
  interval: 4
  list:
    - { material: PLAYER_HEAD, skull_texture: "<frame 1>" }
    - { material: PLAYER_HEAD, skull_texture: "<frame 2>" }

Items from other plugins

Instead of a material, any balloon, part, flipbook frame or category icon can render an item defined by ItemsAdder, Oraxen or Nexo. Point custom_item at the provider and its item id:

custom_item: "itemsadder:namespace:my_balloon"
custom_item: "oraxen:my_balloon"
custom_item: "nexo:my_balloon"

The word before the first colon selects the provider — itemsadder (or ia), oraxen or nexo. Everything after it is that provider's own id, which is why an ItemsAdder id keeps its own colon. The same key works on a part's entry and on each flipbook frame, so a composite or animated model can mix foreign items with plain ones.

No hard dependency. The three plugins are reached by reflection, so ManyBalloons runs whether or not they are installed. A custom_item that cannot be resolved falls back to the balloon's material and leaves a single warning in the console, so a typo is never silent. Set the key to none to turn it off. Add or rename an item in the other plugin, then run /balloons reload so ManyBalloons reads it again.

Crafting recipes

Add a recipe section to make the balloon craftable. With a shape it is a shaped recipe using the characters from ingredients; without one it is shapeless. The crafted item carries the balloon's id, so using it equips that balloon.

recipe:
  enabled: true
  shape:
    - "SBS"
    - "SLS"
    - "SBS"
  ingredients:
    S: STRING
    B: BONE_MEAL
    L: LIGHT_BLUE_DYE
Parts are relative. Every offset is measured from the balloon's own rest spot, so moving offset at the top level moves the whole model and all of its parts together.

Animations

Custom motions live in plugins/ManyBalloons/animations.yml. Define one there, then point a balloon or a part at it with animation: "my_name". No code, no rebuild.

Channels

Each channel holds one wave, a list of waves that add up, or a plain number for a constant.

ChannelWhat it moves
translation.x / y / zPosition in blocks.
rotation.x / y / zRotation in degrees: x is pitch, y is yaw, z is roll.
scaleSize multiplier, where 1.0 is unchanged.

A defined motion

bob_and_drift:
  translation:
    y: { wave: sine, amplitude: 0.15, frequency: 0.12 }
    x:
      - { wave: sine,   amplitude: 0.20, frequency: 0.10 }
      - { wave: cosine, amplitude: 0.10, frequency: 0.23, phase: 1.57 }
    z: 0.5
  rotation:
    y: { wave: linear, amplitude: 1.0, frequency: 0.05 }

Wave fields

FieldWhat it does
wavesine (default), cosine, triangle, sawtooth, square or linear.
amplitudeStrength of the wave. Default 1.0.
frequencyRadians per tick. The period is 2π / frequency. Default 1.0.
phaseStarting angle in radians. Default 0.0.
offsetA constant added to the wave. Default 0.0.

linear grows forever — amplitude × (frequency × t + phase) — so it is the one to use on rotation.y for a continuous spin. A circle is a cosine on x paired with a sine on z at the same frequency, where the amplitude is the radius in blocks.

Scaling around a centre

scale can also be given as base plus waves, to move the centre it breathes around.

scale:
  base: 1.0
  waves:
    - { wave: sine, amplitude: 0.08, frequency: 0.18 }

Built-in motions

These ship with the plugin and win over a custom name with the same key, so the defaults can't be broken. Point any balloon at one by name.

float · float_spin · float_spin_slow · orbit · pulse_float · none · wobble · rock · sway · heartbeat · helix · zigzag · drift · spin · bounce · swing

orbit is special. A part using it circles the balloon centre from its own offset: the radius is hypot(x, z) and the start angle is atan2(z, x). The bundled Solar System instead gives every planet its own custom circle, so they orbit at different speeds.

animations.speed_multiplier in config.yml scales every wave at once. Run /balloons reload after editing this file.

API

Getting started

Hook another plugin into ManyBalloons — shops, quests, crates and menus. The API is free to use.

The API is a small, self-contained jar you compile against. At runtime you obtain it from the Bukkit ServicesManager, so you can also ask whether ManyBalloons is installed instead of crashing with a ClassNotFoundException. Nothing from the plugin's internals is exposed.

Add the dependency

Compile against manyballoons-api with provided scope, so it is never bundled into your own jar. It isn't on Maven Central; download it from the API downloads page.

Maven — once the jar is in a repository you can resolve:

<dependency>
  <groupId>dev.mugi</groupId>
  <artifactId>manyballoons-api</artifactId>
  <version>1.1.0</version>
  <scope>provided</scope>
</dependency>

If it isn't published to a repository you use, install the downloaded jar into your local one:

mvn install:install-file -Dfile=manyballoons-api.jar \
  -DgroupId=dev.mugi -DartifactId=manyballoons-api \
  -Dversion=1.1.0 -Dpackaging=jar

Gradle — drop the jar in libs/ and point at it directly:

dependencies {
    compileOnly files("libs/manyballoons-api.jar")
    // or, once it is in a repository:
    // compileOnly "dev.mugi:manyballoons-api:1.1.0"
}

Declare it in plugin.yml

The server needs to know your plugin uses ManyBalloons so it can load the classes at runtime.

depend: [ManyBalloons]
# or, if ManyBalloons is optional:
softdepend: [ManyBalloons]

Use it

BalloonAPI api = Bukkit.getServicesManager().load(BalloonAPI.class);
if (api == null) {
    getLogger().warning("ManyBalloons is not installed.");
    return;
}

// Give a player a balloon (fires BalloonEquipEvent, respects slots and worlds)
if (api.equip(player, "classic_red")) {
    getLogger().info("Equipped classic_red for " + player.getName());
}

// Read what they wear
boolean has = api.hasBalloon(player.getUniqueId());
int free = api.remainingSlots(player);

API reference

BalloonAPI

The interface you get from Bukkit.getServicesManager().load(BalloonAPI.class). Every method must be called from the main thread.

MethodReturnsWhat it does
hasBalloon(UUID)booleanWhether the player wears at least one balloon.
canUse(Player, String)booleanWhether the player may equip that balloon, permission included. Unknown ids are never allowed.
equip(Player, String)booleanAdds the balloon when a slot is free, the world allows it and no listener cancels. Returns whether it was added.
remainingSlots(Player)intFree equip slots, or Integer.MAX_VALUE for admins.
unequip(UUID)voidRemoves every balloon and clears the saved choice.
getEquippedBalloonIds(UUID)List<String>Every equipped id, in equip order.
getEquippedBalloonId(UUID)StringThe first equipped id, or null.
getBalloons()Collection<Balloon>Every balloon loaded from balloons/.
getBalloon(String)BalloonOne balloon by id, or null when no such balloon is loaded.

The Balloon record

An immutable, read-only view of a loaded balloon. It holds only definition data, never per-player state.

AccessorTypeWhat it is
id()StringThe balloon id, e.g. classic_red.
displayName()StringThe name shown on the item and in the menus.
material()MaterialThe item whose model is rendered.
skullTexture()StringBase64 head texture, or null for none.
customModelData()intThe item's custom_model_data, 0 when unset.
customItem()StringThe ItemsAdder/Oraxen/Nexo provider:id this balloon renders, or null when it is built from material().
lore()List<String>Tooltip lines shown with the menu item.
animation()StringName of the motion applied while it's out.
category()StringSub-folder it came from, or "default".
permission()StringNode required to equip it, or null when everyone may.
isPublic()booleanWhether no permission is required to use it.

Events

EventWhat it's for
BalloonEquipEventFired before a player is given a balloon. Cancellable — cancel it and the equip is rejected. getPlayer(), getBalloon().
BalloonUnequipEventFired when a balloon is removed. Notification only. getPlayerId() is always set; getPlayer() and getBalloon() may be null (quit, admin clear).

Listening

@EventHandler
public void onEquip(BalloonEquipEvent event) {
    // Lock one balloon behind a quest, for example
    if (event.getBalloon().id().equals("galaxy")
            && !playerHasQuest(event.getPlayer())) {
        event.setCancelled(true);
    }
}
